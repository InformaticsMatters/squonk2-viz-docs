Data

Want to know what happens to your data out of sight - why it is kept in a database, how structures are indexed, how a histogram is counted? That is in The data centre. You do not need it to use anything on this page.

Data comes in two steps. You make datasets on the Data tab; you then use them on the Design tab, where a Dataset node picks one and charts draw from it. Nothing on the Design tab reads a file or reshapes data any more — if you have a design from an earlier version with a Data Joiner or Calculated Fields node, it still opens, but those nodes are dropped (the application says so once), and you make the join or the columns on the Data tab instead.

The Data tab

The Data tab is the first tab. It lists every dataset in the project’s data store with its row count and number of fields, and marks the ones that hold structures.

Click a dataset to see a Preview of its rows beneath the list, a page at a time. A dataset with more than twelve fields opens on the first twelve; press Show all N fields beside the row count to see the rest (a column you have just added is at the end), and Show first 12 to go back. A structure is shown as (structure) and a missing value as —. The ⋮ at the end of a row opens the actions for that dataset: Preview, Export CSV, Export SDF, Index structures…, Calculate fields…, Calculate molecular properties…, Filter…, Clear filter and Make filter permanent… (these two only while the dataset has a filter), Edit fields…, Join with… and Delete…. A dataset whose structures have been indexed carries an indexed mark beside structures; hover over it to see how. A dataset with a filter on shows how many of its rows you can see (1,245 of 35,090) and a filtered mark.

Importing a file

Import… opens a dialog listing the CSV and SDF files in the project (gzipped ones included). Choose one, give the dataset a name, and press Import. The types of the columns are worked out from every value in the file, not a sample, so a number that only shows up late in the file cannot turn a column into text half way through.

You do not have to put the file in the project first. The same dialog can upload a file from your computer (Choose file…), or import one from a URL. The server downloads that, so the address must be https:// and reachable from the internet; addresses inside a private network are refused. Either way the file is a temporary copy that is removed once the dataset is made, and nothing is added to the project’s files. A file larger than the server’s limit (2 GB unless the administrator changed it) is refused.

If the name is already taken the dialog says it replaces that dataset. A failed or cancelled import leaves the old one exactly as it was.

Jobs

Importing, calculating, editing fields, filtering and joining all run as jobs. A panel beneath the list shows each one with a progress bar and what it is doing, and a large one can be cancelled part way. When a job finishes, its dataset (new, or changed in place) is up to date in the list and the Design tab sees it straight away; Dismiss clears a job from the panel. Only one job at a time runs on a dataset: starting another while one is running is refused.

Changing a dataset, and making a new one

Calculate fields…, Calculate molecular properties…, Edit fields… and Filter… change the dataset itself. It keeps its name, its rows and their ids, so every chart and Dataset node that uses it carries on, with nothing to point at something new. The columns appear when the job is done; until then the dataset is exactly as it was, and if the job fails or you cancel it, it still is. These ask for no name.

Join with… makes a new dataset, because a joined row is a combination of rows: it asks for a name (offering one such as compounds-joined), so a mistake costs nothing and you can keep every stage. Naming an existing dataset replaces it, and the dialog says so before you press the button.

Because these are made to the dataset itself, there is no copy to throw away if one was a mistake. A calculated column can’t be given the name of a field the dataset already has. A column you no longer want can be deleted with Edit fields…, which is for good; Make filter permanent… likewise deletes rows for good, and each asks before it does. If you may want to keep the original, export it first.

Export

Export CSV downloads the dataset as it is: if a filter is on, the rows it shows. Export SDF is offered for a dataset with structures and writes them back out with their properties. The file is streamed by the server, so exporting a large dataset does not load it into your browser.

Delete

Delete… removes the dataset, after asking. A saved design that draws from it shows no data in those charts until a dataset of that name exists again. Datasets made from it are separate and are not affected.

Filtering rows

Filter… hides the rows that fail your criteria. Nothing is copied or deleted: the dataset keeps its name, its rows and their ids, and every chart that uses it, the preview, an export and a join see only the rows that pass. This is not the same as selecting points on a chart, which is for exploring; a filter changes what the dataset is until you take it off. The Dataset node of a filtered dataset says how many rows it is showing.

  • To change it, choose Filter… again. The dialog opens on the filter that is applied. A new filter replaces the old one and is worked out over all of the rows, so rows the old filter hid can come back.
  • To remove it, choose Clear filter. Every row is shown again. Nothing was lost.
  • To keep it for good, choose Make filter permanent…. This deletes the rows the filter hides, after telling you exactly how many, and cannot be undone. The dataset is then just the rows that are left and has no filter. It is refused when the filter hides nothing, or would leave no rows at all. If the dataset’s structures are indexed, the index loses the entries for the deleted molecules, except any a joined dataset made from this one still uses.

A filter is a snapshot: a row limit such as top 500 by SCORE ranks the rows at the moment you apply it, and neither it nor a condition is re-worked when you later calculate a column or change a type. Calculated columns, molecular properties and type changes are made for every row, hidden or not, so they are all there when you clear the filter. While a filter is on, the dialog’s live count is taken over a sample of the rows you can see.

Two things can narrow it, and they work together:

  • Conditions — one per row, such as SCORE < -30. + Add condition adds another, and every condition must hold for a row to be kept, so building a filter up is a matter of adding rows rather than lengthening one expression. Each row is checked on its own, so a mistake is reported against the row that has it. Use or within a row for alternatives: Series == 'A' or Series == 'B'.

    Click a field name to insert it and use the operator buttons, or type. A true/false column is a test on its own — write active, or not active.

  • A row limit — keep the top 500 by value of SCORE. Set both how many rows and which field to rank on; the limit takes effect once it has both. It ranks on the field’s value, not on position in the file, so it is “the best 500”, not “the first 500”. The rows come back in file order; sort a chart however you like afterwards.

Press Apply. While you type, the dialog says how many of a sample of the rows match, so you can tell a promising filter from a mistaken one before committing.

A row with no value in a field being compared is left out. SCORE < -30 skips a pose with no score — and so does not (SCORE < -30), because there is still nothing to compare. If you want the ones without a score, ask for them: isblank(SCORE). notblank(SCORE) is the opposite, and notblank(SCORE) and not (SCORE < -30) is “has a score, and it is not under −30”.

Text is compared with quotes — Series == 'A' — and contains(name, 'acid'), startswith(...) and endswith(...) match within it. Comparisons are case-sensitive.

Indexing structures

A structure is stored as text when a file is imported. That is all that drawing it needs, so a molecule grid, the 3D viewer, the interaction charts and the R-group table all work straight away, and an import of a large SDF file is quick. What text cannot do is be searched: a substructure or a similarity search has to be answered by the database, which needs the structures indexed first.

Index structures… (on a dataset that holds structures) builds that index. The dialog asks which fingerprints to build for similarity searching:

  • a kind (Morgan, Feature Morgan, RDKit, Atom pair or Topological torsion),
  • for the Morgan kinds a radius, and
  • a length in bits (64 to 9192; 2048 is a common choice).

It starts with Morgan, radius 2, 2048 bits. You can build several, and a similarity search uses the first. Remove them all to index for substructure search only. Two fingerprints of the same kind must have the same length. Indexing runs as a job and can take a while on a large dataset. The dataset itself is not changed, and indexing again with other fingerprints replaces the index.

Until a dataset is indexed, a molecule grid built on it shows its structure-search controls greyed out, with a note saying why, and a sketch wired into it filters nothing. A Calculate fields…, Calculate molecular properties… or Edit fields… leaves the index as it is (deleting the structures field in Edit fields… is the exception: it deletes the index too), and a Filter… does not touch it either (the hidden rows are simply not searched; Make filter permanent… does remove the entries of the molecules it deletes, unless a joined dataset still uses them). A Join with… gives the new dataset the same index rather than building another, for the first dataset that has one.

About the database

About database…, at the top of the Data tab, shows how big this project’s tables are and how much of that is dead space. It is there when the project’s data lives in a database (the Data Manager’s app does; the demo gallery’s in-browser datasets do not). Everything in it is about this project only.

It lists every table, largest first (click a column heading to sort by it, and again to reverse): each dataset, the table behind each structure index (with the datasets that use it), and a few internal tables the service keeps for itself. For each you see:

  • Size and, separately, the part of it taken by indexes.
  • Rows and Dead rows. A row that has been deleted, or replaced by a newer version of itself, stays on disk as a dead row until the space is reclaimed. Dead is shown in colour once a fifth of a table is dead.
  • Last vacuum: when the table was last cleaned up, by you or by the database itself.
  • For a dataset with a filter on, how many rows the filter is hiding. Making the filter permanent would delete them.

The database cleans up on its own, so you rarely need to do anything. Two buttons are there for when you do:

  • Vacuum makes the space of dead rows reusable and refreshes the statistics the database uses to plan queries. It runs while the table is in use, and it does not make the files smaller: the space is kept for new rows. Vacuum all does every table.
  • Compact rewrites the table and its indexes into new files, which gives the disk space back. Use it after deleting a lot of rows, for example after making a filter permanent. It asks first, because it holds the table exclusively while it runs: a chart reading the table waits, and if the table is in use at that moment the job stops with a message and changes nothing. If something else is still working with older versions of the rows while it runs, it cannot remove every dead row; run it again when the project is quiet.

Both run as jobs, listed with the others, and the numbers refresh when they finish. Only one maintenance job runs at a time.

Calculating molecular properties

Calculate molecular properties… (on a dataset that holds structures) adds RDKit properties as new columns, worked out from the structure of each row. Unlike a search it does not need the structures indexed. Choose the structure field (the first is offered) and tick the properties you want. The columns are added to the dataset itself, after the ones it has, and its rows and their ids are unchanged.

Group Properties
Size molecular weight, exact mass, atom count, heavy atom count, heteroatom count
Lipophilicity & polarity logP, TPSA, Labute ASA, fraction sp3 carbons
Hydrogen bonding & flexibility H-bond donors, H-bond acceptors, rotatable bonds, amide bonds
Rings rings, aromatic / aliphatic / saturated rings, heterocycles, aromatic / aliphatic / saturated heterocycles and carbocycles, spiro atoms, bridgehead atoms
Text molecular formula, canonical SMILES, InChI, InChIKey, Murcko scaffold

Molecular weight, heavy atoms, logP, TPSA, H-bond donors and acceptors and rotatable bonds are ticked to start with; All and None act on a group. Each column is named with a prefix and the property, such as RDK_logp and RDK_hac. If the dataset already has a field of that name the dialog says so and the button stays disabled: change the prefix. A structure RDKit cannot read leaves its cells empty rather than stopping the job, and the dataset records how many there were. A molecule with no ring has no Murcko scaffold, which is also left empty. A dataset whose structures are indexed keeps its index.

Editing fields

Edit fields… is the one place to tidy a dataset’s columns, mainly before you draw anything from it. The dialog has a row for every field:

Column What it does
Field The name, which you can change.
SQL type What the database really calls the column (bigint, double precision, text, boolean). Read-only, and read from the database, so it is never a guess.
Type The type the application treats it as (string, integer, float, boolean); change it with the menu.
Index None, B-tree, Hash or BRIN. An index makes selections and searches on that field quick on a large dataset; the kinds on offer suit the field (BRIN only for numbers).
🗑 Mark the field for deletion. It is struck through until you press Apply, and ↶ puts it back.

Nothing happens until Apply, and then all of it happens or none of it does: if anything fails, or you cancel the job, the dataset is exactly as it was. The dialog says what is wrong with an edit as you type it (a name that is already taken, an index that does not suit the field).

  • Renaming a field changes it everywhere in the dataset, but anything bound to the old name (a chart’s axis, a node in a design) has to be bound to the new one again. The dialog warns you. A field used by the filter that is applied cannot be renamed or deleted until the filter is cleared.
  • Deleting a field removes the column and its data for good. The dialog asks once more, with the names, before it does it. Deleting the structures field also deletes the structure index, leaving a plain data table (the index is kept if another dataset, such as a join, still uses it).
  • Changing a type rebuilds the column, which also drops its index; choose one again in the same edit if you want it. Structure fields can be renamed and deleted, but not retyped or indexed.
  • Fields keep their place; a calculated column you added is still at the end.

Changing a type

The type of each field is worked out when a file is imported, and it decides what the field can be used for: only numeric fields are offered as axes, for instance. When the guess is wrong, choose the type you want. Each is rebuilt as a new column and replaces the old one, in the same place, only when they are all ready. A common case is a column of numbers that was read as text because one cell says NA.

A field that holds structures has no type to choose: its type is what lets the structure searches work.

A value that does not fit the new type is left missing, rather than stopping the change, and the dataset’s source line says how many there were. So NA becomes a blank in an integer column and the rest of the column becomes numbers. What fits:

To From text From integer From float From boolean
string as it is its digits its text true / false
integer a whole number, blanks ignored as it is only if it is whole (3.0, not 3.5) 1 / 0
float a decimal or exponent number (4.5, 1e3, .5) as it is as it is 1 / 0
boolean true / t / false / f, any case 1 is true, 0 is false 1 is true, 0 is false as it is

Integers beyond about 9 × 10¹⁵ (what the browser can hold exactly) are missing. Everything else about the dataset is unchanged: the same rows, with the same ids, and any structures keep their searches. A field that becomes text is treated as a category again if it has few distinct values.

Joining datasets

Join with… combines two or more datasets into one, matching rows on a key column, so a chart can draw on columns from several files at once.

Start from the primary dataset — the one you opened the menu on — and the dialog lists it first. Use + Add dataset for each further input, and for each choose the key column whose values are matched. Then choose which rows to Keep:

  • Inner — only rows whose key is in every dataset.
  • Left — every row of the first dataset, with matches from the others.
  • Full — every row from every dataset, matched where keys agree.

A column name that two datasets share is prefixed with the name of the dataset it came from, to keep them apart. A row with no key value never matches. The joined dataset’s rows are numbered afresh, since a row is now a combination.

The join is a copy made inside the database: it does not follow later changes to its inputs, it uses only the rows each input’s filter leaves, and it shares the first structure column’s search index with its source. How a join works has the detail.

Calculating fields

Calculate fields… adds columns worked out row by row from the columns already there. They are added to the dataset itself, so every chart that uses it offers them as if they had been in the file.

Use + Add column for each one.

Click a field name to insert it, or type it; the operators + − × ÷ ^ and the functions abs, ceil, exp, floor, ln, log10, max, min, pow, round, sqrt are all there as buttons, and hovering one explains it.

Two things are worth knowing:

  • Columns can build on each other, in the order listed. selectivity may refer to pIC50 if pIC50 is above it; the other way round is reported as an error, with a note to move it up.
  • A value that cannot be worked out leaves that cell blank — a missing or non-numeric input, a division by zero, the log of zero or a negative. The row stays in the dataset and counts towards the chart’s missing figure. An expression that does not parse, by contrast, adds no column at all and says what is wrong: a whole column of blanks would look like a problem with your data rather than with the expression.

Note that ^ binds more tightly than a leading minus, so -2^2 is -4 — the mathematical convention, which differs from Excel’s.

The rows and their ids are unchanged, so a selection or filter wired across the dataset keeps working. You can calculate again from the columns you added, and join the dataset to others.

Dataset node

On the Design tab, a Dataset node picks one of the datasets on the Data tab. It is usually the first node you add, because every chart needs one.

Choose from the dropdown; the node then lists the fields of that dataset with the type of each — integer, float, string, or molecule for a column holding structures. Those types decide what a field can be used for: only numeric fields are offered as axes, and only a molecule field can be a structure field. With no datasets yet the dropdown says so and points you to the Data tab.

If a filter on the Data tab is hiding some of the dataset’s rows, the node says so (Filtered: 120 of 3,500 rows): every chart wired to it draws only those rows. When you rename or delete a field with Edit fields…, the node follows, and a chart that used the old field has to be given a field again.

The node stores the dataset’s name, so a saved design finds its data again in a new instance as long as a dataset of that name exists there. Calculating, filtering and editing fields all change a dataset in place and keep its name, so none of them leaves a design pointing at the wrong dataset.

Output: dataset.

FileSelector

Supplies structure files — a receptor, a reference structure — to the nodes that need one. It is the only way a protein reaches the 3D viewer or either of the interaction views.

Pick from Add available file… and the entry is linked to that project file. A linked entry says so, and is re-resolved against the project each time the visualisation is loaded — which is what lets a saved visualisation work in a new instance, whose internal addresses are different. Typing a location by hand instead is allowed, but unlinks the entry.

If a linked file is no longer in the project, the node says so rather than silently doing nothing.

Output: files. A MoleculeViewer3D loads every file on the port; the two interaction views use the first as their receptor.
