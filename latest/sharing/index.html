Sharing a visualisation

You can hand an instance, or one saved visualisation in it, to a colleague who is on the same Data Manager project. What they can do follows their role on the project, which the Data Manager decides, not you.

Sharing is available only on installations that have switched it on. Ask whoever runs your Data Manager if the Copy link button below does nothing useful for your colleague: on an installation without it, an instance has a single user, its owner.

Who can open it

Role on the project Can open a shared instance?
Administrator, Editor Yes, with the same rights as you: they can build, save, rename and delete visualisations and import data
Observer Yes, view only (see below)
Not on the project No

Everyone with an editor or administrator role has the same rights, so share with people you would trust to change or delete the project’s visualisations.

What an observer can do

An observer can look and explore, but cannot change the project. The app bar says View only.

An observer can An observer cannot
Open any saved visualisation (Load, or a shared link) and export it Save, rename, delete or import visualisations; start a new one
Select, filter and mark in the charts, and see what is wired to what Add, delete or rewire nodes; add, rename or close views; take a chart out of a view
Change a chart’s settings (axis ranges, colours, fields), move and resize charts, open a view in its own window Keep any of those changes: they last until the page is reloaded and are never saved
Open the settings dialog and try preferences Save preferences, or turn on Auto save
Explore the datasets through the charts See the Data tab, or import, derive, edit or delete a dataset

What an observer changes on screen is theirs alone: it is not saved, and nobody else sees it. The restriction is enforced by the server as well as hidden in the page, so it cannot be got round by other means.

Two things follow from the Data Manager checking each person:

  • Who saved what is recorded accurately. The Load dialog shows who first saved each visualisation and who saved it last, by their own name, not the name of whoever launched the instance.
  • A session can lapse. If your sign-in expires, a message appears with a Reload button; reloading signs you in again. Nothing is lost that you had already saved.

Sharing one visualisation: Copy link

Open a saved visualisation and press Copy link in the app bar. The link looks like …/instance-1234/?viz=My%20analysis, and opening it loads that visualisation straight away.

  • The button is greyed out until the visualisation has a name, that is, until you have saved it. The link always opens what is saved, not unsaved changes on your canvas.
  • The address in your browser follows the visualisation you have open, so copying it from the address bar does the same.
  • If the visualisation has been deleted or renamed since the link was made, the instance opens as normal and says it could not find it.

A link is a pointer, not a password. Anyone who opens it is still checked against the project’s members and their role, so forwarding it to someone outside the project gives them nothing.

If the instance has gone

The Data Manager shuts an instance down when it has been idle for long enough. Only a project editor or administrator can launch a new one, so an observer cannot bring a shut-down instance back. Ask someone who can. Your saved visualisations are still in the project; see Getting started.
